## Resource and disposal map

There are **no plugin `setInterval`s, background services, schedules, file watchers, realtime subscriptions, or MutationObservers**. Test/audit timers are separate from production resources.

## Edge cases and live checks

- **Zero items:** unit and real browser synthetic response show the empty-state message and zero meters. Disabled providers skip CLI and host reads entirely.
- **1,000 logins / hosts:** bounded RPC concurrency, compact serialization, KV size handling, and virtual row counts tested. Browser scrolled to the final machine at row 2001 with eight mounted rows: [trace](scroll.json).
- **One login / 1,000 windows:** virtualizes inside a login; browser reached Window 999 at row 1000 with seven mounted rows: [trace](huge-windows.json).
- **Offline / slow / error storms:** no polling while offline/hidden; per-call deadlines tolerate ignored abort signals; 20-second frontend feedback deadline; backend retry cooldown and detached waiters tested. All-host failure retains old cache through failed background refresh; partial failure is explicitly shown.
- **Rapid navigation:** 20 frontend remounts share a slow RPC; 1,000 cancelled waiters retain no view callbacks. Poll generations reject stale replies; invalidation rejects an old in-flight configuration.
- **Reload mid-task:** fake SDK reload aborts a hung usage read, with no stale writes/retries. Process tests cover probe cancellation, no spawn after abort, bounded noisy stdout and TERM/KILL cleanup. No actual reset credits were consumed to test this.
- **360 px / resize:** final mobile shell was ~255 px wide with equal scroll/client width, virtual viewport 240 px and Reload within the viewport. Resizing between 360 and 1280 worked; the host closes disclosures at the breakpoint, and reopening works. Fixed nested scroll height and horizontal clipping found by the live test.
- **Theme:** toggling the isolated page's dark class changed computed foreground from `rgb(55, 53, 47)` to `rgb(199, 199, 197)` without width overflow. Restored afterward.
- **Motion:** meters use scaleX, virtual positioning uses translateY, spinner uses transform, skeleton pulse uses opacity. Removed button color transitions and locally disabled the host disclosure's height transition. Live spinner keyframes contained only transform. Activating the shipped reduced-motion rule in CSSOM yielded zero active animations: [trace](motion.json). Browse did not support OS media emulation; this checks the real CSS rule, not OS preference propagation.
- **Actual service:** after the final reload, unmocked RPC returned HTTP 200, four logins, three hosts and one unavailable host in 14,973.8 ms; subsequent cached read was 6.9 ms. The final error-policy reload also passed an [unmocked wire check](live-final.json). UI had five meters, no error alerts, and the partial-availability notice. [Cold](live.json), [cached](live-cached.json). The reported small-list scroll width includes the intentional 200%-width divider pseudo-elements; the host clips horizontal overflow. Synthetic virtual/mobile content did not clip text after the layout correction.

## Verification and remaining tradeoffs

`npm ci --include=dev` completed against the lockfile, installing 250 packages with zero reported vulnerabilities. `npm run typecheck` passed. `npm test` passed **53 tests** (37 Node tests and 16 Vitest tests). `git diff --check` passed. Ran `bb plugin build bb-plugin-reserve` and `bb plugin reload reserve` after committing each runtime correction. Final ID/source remained `reserve` at the confirmed permanent path. [Plugin source/status check](plugin-status.json).

The synthetic 1 ms host batch is deliberately **slower in wall time** with bounded concurrency: 19.6 → 155.4 ms, while peak simultaneous calls falls from 1,000 to eight. This protects hosts/RPC infrastructure rather than claiming lower time for an unrealistically cheap unlimited batch.

The transferred app JS grew from 5,910 to 14,613 encoded bytes (including measured virtualization and lifecycle protections); CSS from 3,075 to 3,100 bytes. This is a modest startup cost for bounded large-list rendering. No benchmark claims a faster cold external RPC: the live cold fetch reached the 15-second fleet budget. Warm snapshots remain immediate. Fleets exceeding the KV cap reload from live data after process restart. Snapshots and virtual position arrays remain O(current dataset), not O(visible rows); transport/data pagination would need a separate product/API design for millions of items.

The audit establishes concrete limits and tested behavior, not exhaustive proof for every OS, provider failure, arbitrary input size, or network stack. In particular, SDK transports without cancellation cannot be physically stopped by this plugin; owned waits/listeners are disposed and the frontend avoids creating replacement transports while one is pending.

## Reproduce

Run `node --experimental-strip-types audit/measure.ts` and `node --experimental-strip-types audit/format.ts` from the package. Use the baseline Reserve source to reproduce before results; compare JSON fields, not unrelated server handler totals (those persist across reloads).

For a disposable authenticated BB browser: open Usage, run [setup-browser.js](setup-browser.js), refresh once, then evaluate [browser-trace.js](browser-trace.js). The fixture intercepts only this session's `getUsage` reads and does not change backend state. For the baseline shape, add `hosts` to each login. Restore `window.fetch = window.reserveAuditFetch`, then reload/close that browser. Both audit browser runs were released, and the last session's original network was restored before release.
